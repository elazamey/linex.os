- Policy Engine responsibility evaluate Action, validate policy applicability, evaluate capability requirement, actor, resource, scope, risk, environment, context, approval state, network state, policy constraints, return deterministic decision, explanation/reason, obligations/requirements, policy version, emit policy decision event, must NOT execute shell, call sudo, modify files, send network request, modify Capability Registry, silently authorize, silently downgrade risk, turn UNKNOWN into ALLOW.

- Alternative C: Allow LLM to be final authority, allow Policy to infer permissions from natural-language intent alone, allow last rule wins, allow UNKNOWN→ALLOW, allow generic approval "allow this Agent anything", allow silent policy mutation by Agent/LLM, allow learning to activate policy changes automatically, allow Policy to execute, self-grant capabilities, act as Executor, Verifier, become LLM — Rejected because violates core principle AI PROPOSES→POLICY EVALUATES→AUTHORIZATION CONFIRMS→EXECUTION AUTHORITY EXECUTES→VERIFIER PROVES, violates deterministic, fail-closed, default deny, DENY wins over ALLOW, UNKNOWN→BLOCKED/DENY, approval bound to specific action/context, approval expires, dry-run authorization ≠ real execution authorization, production requires stronger policy, network-unverified high-risk BLOCKED, untrusted provenance BLOCKED, secret values never belong in ordinary PolicyRequest, local authorization ≠ production authorization, policy version immutable for a decision, every decision has explanation/reason, every side-effect decision declares evidence requirements, policy conflict cannot resolve to implicit ALLOW, policy failure fail-closed, policy cannot mark VERIFIED, cannot call Executor, cannot bypass Execution Authority, violates security invariants POL-01 to POL-30.
