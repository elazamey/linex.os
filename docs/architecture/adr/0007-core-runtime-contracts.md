## Alternatives Considered

- Alternative A: Start building Core Runtime directly with assumed language (Python/Node/Rust) and assumed DB/event bus — Rejected because would assume implementation before interfaces stable, lead to big monolithic app not platform architecture, violate Contract First principle, risk of vendor lock-in, not free-first, not low-resource mode aware, would violate P8 open decisions PENDING

- Alternative B: Define only Runtime Contract without Task/Run/Action/Event/Result/Evidence — Rejected because 5 core contracts are interdependent, need all 5 to define language LINEX.OS speaks internally, Task→Action→Event→Result→Evidence flow is central, missing one would leave gaps, Agent would still be tied to Linux or LLM provider

- Alternative C: Define contracts with implementation language chosen (e.g., Python) — Rejected because P8 open decisions explicitly PENDING with criteria, no technologies chosen merely to fill gap, P9 must be vendor-neutral free-first self-hostable local-capable no mandatory paid API/cloud DB, implementation language decision belongs to P18 Technology Selection ADRs after all contracts P9-P17, not now

- Chosen: Alternative D: Contract First → Implementation Later with 5 core contracts plus lifecycle state machines, no implementation language, no product code, only contracts/schemas/state machines/invariants/tests, respects P8 freeze, enables platform architecture
