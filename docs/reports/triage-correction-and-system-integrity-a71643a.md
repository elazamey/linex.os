## 4. مراجعة W2 المعمّقة (قبل الدمج، كما طلب المالك)

**التأكيد:** `.github/workflows/ci.yml` Job 4 (خطوة CI-H4) كان يثبّت بـ:

```
sudo apt-get update -y
sudo apt-get install -y --no-install-recommends $P3_PKGS
```

أي **خارج** `ops/security/privilege-gate.sh` — المسار الذي يعلن المشروع أنه الوحيد.

**اكتشافان جديدان يجعلان W2 أخطر من توصيفه الأولي:**

1. **`python3` غير مُدرَج في قائمة سماح البوابة.** قائمة CI تضمّ `python3`؛ البوابة كانت ترفضه.
   فلو مُرِّر الأمر عبر البوابة كما كان، **لَفَشِل**.
2. **القائمة تخلط أسماء الأدوات بأسماء الحزم:** `find` و`awk` في حلقة CI هما أمران لا حزمان
   (`findutils`، `gawk`)، و`package-install find` → BLOCKED.

**النتيجة المقيسة:** تمرير مدخلات CI الـ18 عبر البوابة كان سيفشل في **3 مداخل من 18**، فادعاء
«البوابة هي المسار الوحيد» لم يكن **قابلاً للتنفيذ** أصلاً، لا مجرد مُتجاوَز.

**عيّنة من الحكم بعد الإصلاح (على المدخلات نفسها):** `governance-consistency.test.sh` → G2/G3/G4
PASS، وG5 يؤكد عدم وجود أي `sudo apt|dpkg` في `ci.yml`، وG6/G7 يؤكدان الوساطة والفشل المُغلق.

**خصائص مُثبتة بالتشغيل لا بالوصف:**

- مسار مسموح واحد: قراءة ملف داخل مساحة العمل. الرد على stdout، وأثر الحوكمة على stderr.
- مرفوضات مُختبَرة: `..`، مسار مطلق، هروب بـsymlink، `.git/config`، ملف مفقود، ملف >64KiB →
  كلها `DENY` و`exit 3`، ولا شيء يُنفَّذ.
- قدرات بلا منفّذ تبقى مرفوضة: `run_command`، `install_package`، `network_fetch` → `exit 3`.
- الكتابة تتطلب موافقة: `write_file` → `exit 4`، ولم يُنشأ أي ملف.
- نص المستخدم لا يُنفَّذ: `--text '$(whoami); rm -rf /'` يُعاد حرفياً.
- الدليل **خالٍ من المحتوى**: يُخزَّن `sha256` فقط؛ الفحص يتأكد من غياب نص الملف عن السجل.
- الدليل **إضافي فقط**: السطر الأول لم يتغيّر بعد كتابة سطر ثانٍ (مقارنة بصمة).
- الرد المُسلَّم = الرد المُدلَّل: البصمة تُحسب على البايتات المُخرَجة فعلاً.

**ونتيجة مهمة للنزاهة:** حراس التجميد القائمة في المستودع (`contracts.test.sh` TEST 10،
`capability.test.sh` TEST-44، `execution-authority.test.sh` TEST-35) **لا تزال تمر كما هي**
بعد إضافة الـslice، لأن Slice 0 يستعمل Bash الموجود ولا يضيف لغة ولا يختار تقنية (ADR 0012).
